# owner CI SDK distribution artifact

This directory is the owner-side release lane for the complete DND5E 2014
runtime SDK: it turns the reviewed `dist/` bytes of one commit into a
deterministic zip, a manifest and a receipt, and the workflow publishes exactly
those three files as the assets of a `release-*` GitHub Release cut from `main`.

```
tools/owner-ci/dist-files.json   distribution whitelist (zip name -> repo source, role)
tools/owner-ci/zip.mjs           deterministic zip writer/reader (no dependencies)
tools/owner-ci/release.mjs       inventory / assemble / verify
```

## Distribution surface

The consumer (`mt-foundry-compat`, `web/runtime-sdk/dnd5e-runtime/`) consumes
five files. Four are owner bytes and are the zip members; the fifth is the
consumer's own pin and is never fabricated here.

| zip member | repo source | role |
| --- | --- | --- |
| `dnd5e-runtime.mjs` | `packages/dnd5e-runtime/dist/dnd5e-runtime.mjs` | `artifact` |
| `dnd5e-runtime.sdk-manifest.json` | `packages/dnd5e-runtime/dist/manifest.json` | `sdk-manifest` |
| `dnd5e-runtime.LICENSE.txt` | `packages/dnd5e-runtime/LICENSE` | `license` |
| `dnd5e-runtime.NOTICE.txt` | `packages/dnd5e-runtime/NOTICE` | `notice` |
| `dnd5e-runtime.manifest.json` | generated by the consumer's `tools/sync-dnd5e-runtime.mjs` | consumer pin |

The zip root *is* the distribution directory, so the four members drop in by
name. `--distribution-dir` makes `verify` prove that byte equality, and bind the
consumer pin's `commit` / `sourceHash` / `buildHash` / `sdkManifest.sha256` /
identity fields to the released artifact.

## Deterministic recipe

`arcane-dnd5e-runtime-sdk-zip/1`: store (no compression), paths sorted by UTF-16
code unit, fixed `1980-01-01T00:00:00Z` DOS timestamp, `0644` regular files,
UTF-8 names, no extra field and no archive comment. The byte rules are copied
verbatim from `octopus-system-artifact-zip/1`; the recipe id is a separate
namespace on purpose, so this artifact can never be mistaken for a BRP or dnd5e
fork coordinate.

## Local reproduction

```sh
node tools/owner-ci/release.mjs inventory --root .
node tools/owner-ci/release.mjs assemble --root . --out-dir <dir-outside-repo>
node tools/owner-ci/release.mjs verify \
  --artifact <dir-outside-repo>/dnd5e-runtime-sdk.zip \
  --manifest <dir-outside-repo>/dnd5e-runtime-sdk-manifest.json \
  --receipt <dir-outside-repo>/dnd5e-runtime-sdk-receipt.json \
  --root . [--distribution-dir <consumer-sdk-dir>]
```

`assemble` refuses an output directory inside the repository: the repository
content audit rejects `.zip` files, and release bytes must not become tracked
content.

## What `assemble` proves before it writes anything

- every whitelist file exists and its worktree bytes equal the git blob at the
  released commit (dirty or drifted bytes are a hard failure, not a warning);
- the SDK manifest identity (`schemaVersion` 1, `runtimeKind` `full`,
  `factoryName` `initializeDnd5eRuntime`, module id, `contentPolicy`
  `runtime-only`) and its artifact/source hashes agree with the packaged bytes
  and `src/source-baseline.json`;
- `packages/dnd5e-runtime/dist/` contains exactly the two whitelisted dist files;
- the LICENSE member is a full Apache-2.0 text and the NOTICE member keeps the
  ArcaneDesk attribution;
- two builds produce identical zip bytes;
- the zip parses back through the recipe reader, unpacks into exactly its member
  set, and every unpacked file equals the source tree.

The receipt is written only after all of that passes; `runUrl` stays `null`
outside Actions. Manifest and receipt use the
`arcane-dnd5e-runtime-sdk-set-hash/1` namespace over
`path\nsize\nsha256\n` lines, sorted by path.

## Release coordinate (D2/D8)

`release-publish` only runs for a `release-*` tag pushed from `main`
(`git merge-base --is-ancestor <tag commit> origin/main`), after the test job
and the artifact job are green. It verifies the downloaded bytes again, requires
the artifact commit to equal the tag commit, refuses to overwrite an existing
release, uploads the three fixed-name assets to a draft, re-checks asset names
and sizes, and only then publishes. Branch pushes and pull requests upload the
same three files as private run artifacts (retention 30 days) and never create a
release.
